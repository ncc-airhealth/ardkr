# recall-knowledge

이 레포는 **모든 지식을 레포 안에** 둔다(agent-native). 따라서 어떤 작업이든 **시작 전에**
관련 지식을 먼저 조회해, 과거 결정을 되풀이하거나 뒤엎지 않고 기존 맥락 위에서 작업한다.

## 언제 쓰나

- 새 collection을 추가하거나 기존 데이터를 가공하기 전
- 특정 기관·데이터셋(예: "국토부 건물통합정보")을 처음 다룰 때
- 아키텍처/운영 방식에 영향을 주는 결정을 내리기 전
- "이거 예전에 정한 것 같은데?" 싶은 순간

## 절차

1. **목차부터 훑는다.**
   - `knowledge/index.md` — 번들 전체 구조
   - `knowledge/decisions/index.md` — 확정된 설계·운영 결정 목록
   - `knowledge/principles.md` — 상위 원칙 (여기에 어긋나는 작업이면 멈추고 논의)

2. **키워드·태그로 검색한다.**
   - 다루려는 기관명, 데이터셋명, 개념(예: `proj:code`, `deprecated`, `checksum`,
     `provenance`, 좌표계, 결측값)으로 `knowledge/` 전체를 grep.
   - 각 문서 frontmatter의 `tags:`를 활용.

   ```bash
   grep -rin "<키워드>" knowledge/
   ```

3. **관련 결정을 실제로 읽는다.** 요약만 보지 말고 결정 문서 본문의 *결정 / 근거 /
   기각한 대안 / 미해결*을 확인한다. bundle-relative 링크(`/decisions/...`)를 따라간다.

4. **데이터에 관한 사실은 knowledge/가 아니라 STAC에 있다.** 특정 데이터셋의 좌표계·컬럼
   의미·정정 이력·기관 해명은 해당 collection의 STAC 메타데이터(`description`의
   `[correction]` 마커 포함)를 확인한다. knowledge/는 그 외 간접 지식(처리법·문의 이력·
   휴리스틱·결정)만 담는다.

5. **찾은 것을 사용자에게 요약 보고한다.** 특히:
   - 지금 하려는 작업과 **충돌**하는 과거 결정
   - 해당 기관·데이터셋에 대한 **주의사항/휴리스틱**
   - 재사용할 수 있는 **처리법·연락 경로**
   - 관련된 **미해결(open question)** 항목

## 아무것도 없으면

관련 지식이 없다면 그 사실을 알리고 진행한다. 그리고 이번 작업에서 새 지식이 생기면
`capture-knowledge`로 반드시 남긴다.
