# 인프라 — 팀 소유 R2, 계정·설정은 암묵지 예외

## 결정

- 오브젝트 스토리지는 **Cloudflare R2**, 버킷은 **팀 소유**다(개인 계정 아님).
  - 담당자가 떠나도 데이터가 개인에게 묶이지 않아, 인프라가 특정 개인에게 의존하지 않는다.
- **예외 구역은 비밀·세부 설정으로 좁힌다**: 계정 자격증명·루트 접근·결제 정보, 버킷 세부 설정(수명주기 규칙·CORS 등 콘솔 클릭으로 관리하는 항목)은 **레포 밖 암묵지**로 둔다.
  - 계정 정보는 비밀이라 git에 넣지 않는다.
  - 세부 설정은 초기 버킷 생성 1회와 키 발급만 하므로 콘솔 클릭으로 관리하고 IaC·문서화 비용을 들이지 않는다.
- **비밀이 아닌 포인터는 레포에 기록한다**(2026-07-21 결정 변경, 근거는 아래).
  - 버킷명: `geovars`
  - 엔드포인트: `https://0338bb0b6b16f3ee66ce6c88e715f9a5.r2.cloudflarestorage.com`
  - 스토리지 클래스/티어 이름: 일반 클래스(Standard)
    - 콜드 티어 미사용
  - 자격증명(키) 발급 요청 대상(직책/채널, 실명 아님): `hangm0101@ncc.re.kr`

## 왜 이것만 예외인가 (명시)

- [/principles.md](/principles.md)는 "모든 지식은 레포 안에"를 요구하고 [/decisions/reproducibility.md](/decisions/reproducibility.md)는 재현성·투명성을 요구하지만, 인프라는 이 두 원칙의 명시적 예외 구역이다.
  - 나중에 "왜 이것만 예외지?"라는 혼란을 막기 위해 예외임을 여기 명시한다.
- 결정 변경(2026-07-21): 원래는 단순성을 위해 비밀이 아닌 포인터(버킷명·엔드포인트·티어링 정책·자격증명 요청처)까지 통째로 암묵지 예외로 두었으나, "담당자 교체" 목표와 직접 충돌한다고 판단해 뒤집었다.

## 감수한 비용

- 후임 담당자는 자격증명 자체(키·계정 접근)를 레포에서 찾을 수 없고, 최초 발급은 사람에게 직접 요청해서 받아야 한다.
  - 다만 버킷명·엔드포인트·티어 이름·키 요청 대상은 레포에 있어, 인수인계 비용이 "접근 자체를 모름"에서 "키 발급만 사람에게 요청"으로 줄어든다.
- 콜드 티어링 정책이 적용되어 있는지는 여전히 레포만으로 확인할 수 없다([/decisions/reproducibility.md](/decisions/reproducibility.md)).
